# Модули mikto — справочник

15 модулей идут в порядке зависимостей. Любое подмножество — через
`--modules a,b,c`. Зрелость: **reference** = обкатано в этом коде,
**preview** = полезно уже сейчас, но ещё растёт.

Все модули следуют одному контракту (см. `include/mikto/module.hpp`):
не расширяем scope, не меняем состояние цели, всё выдаём через общую запись
находки, каждый внешний запрос учитываем по провайдеру.

## assets — DNS + TLS-сертификат (preview)

* Собственный RFC 1035 DNS-клиент (UDP, без внешних библиотек): A, AAAA, MX,
  NS, TXT, SOA, CAA, PTR; фолбэк на `getaddrinfo`, если UDP/53 закрыт.
* Проверка политик SPF / DMARC / CAA; проверка висячих MX/NS.
* `--deep`: AXFR-проба передачи зоны (read-only; удачная передача
  *сообщается*, но данные не сохраняются).
* Осмотр TLS-сертификата: issuer, сроки, SAN. Имена из SAN попадают в
  разведку — **не сканируются**.
* Вход: имя/IP из scope. Выход: `dns_records`, поля сертификата, находки
  (wildcard DNS, отсутствие CAA, истекающий сертификат…).

## whois — регистрационные данные (preview)

* WHOIS по TCP/43, IANA referral → авторитативный сервер. Без ключей.
* Регистратор, даты создания/обновления/истечения, контактные e-mail'ы,
  неймсерверы.
* Находки: домен скоро истекает, приватный прокси против прямых контактов.
* RDAP-фолбэк, если порт 43 закрыт.

## subdom — пассивный поиск субдоменов (preview)

* Источники опрашиваются параллельно: crt.sh, urlscan.io, Wayback Machine,
  HackerTarget. Всё без ключей.
* Wildcard-детект (проба случайной метки) отсекает фантомные субдомены.
* Найденные имена идут в отчёт и граф разведки; они **не сканируются**
  (scope не расширяется). Разрешение параллельное (12 воркеров).

## emails — сбор e-mail'ов (preview)

* Сбор из certificate transparency и страниц, уже скачанных с цели.
* Оставляем только адреса на домене цели.

## emailsec — гигиена почтового домена (preview)

* Только DNS, пассивно. Переиспользует DNS-данные `assets`, не переспрашивая.
* Качество SPF: `+all` — критично, отсутствие `all`, лимит lookups RFC 7208,
  приватные диапазоны в механизмах.
* DMARC: `p=none`, `pct<100`, `sp=none`, кривые записи.
* Проба DKIM-селекторов (16 частых), MTA-STS (RFC 8461), TLS-RPT (RFC 8460),
  DNSSEC (DNSKEY), позитивные заметки по CAA.

## ports — TCP-скан + детект сервисов (reference)

* TCP connect-скан; safe ≈55 кураторских портов, deep = 1–65535.
* Лестница проб на каждый открытый порт: баннер → TLS handshake → HTTP GET →
  Redis PING. Каждое опознание несёт уверенность: `confirmed` / `header` /
  `banner` / `guess`.
* Мульти-продуктовые `Server:` (Apache + OpenSSL + подсказка ОС),
  релизные буквы в стиле OpenSSL (`1.1.1d`), пассивная догадка по ОС.
* Анализ обмана: honeypot-баннеры (Cowrie, Kippo, Dionaea, OpenCanary,
  Honeyd, T-Pot), неправдоподобно старые SSH-баннеры, прокси-sinkhole
  (≥3 порта с байт-в-байт одинаковыми ответами), несовпадение протокола и
  порта, TLS на неожиданных портах, голый HTTP на 443, маркеры
  перенаправляющего прокси.

## infra — обогащение инфраструктуры (preview)

* Без ключей: Shodan InternetDB (порты, CPE, CVE, теги), ipwho.is → ip-api
  (гео/ASN/хостинг-организация), лента репутации URLhaus.
* Опциональные ключи добавляют глубину: `--shodan-key` (полный host API с ОС),
  `--censys-key` (софт/CPE по сервисам → питает модуль cve, метки, ASN/rDNS,
  гео-фолбэк).
* 24 ч дисковый кэш на источник (`~/.cache/mikto/`), самопейсинг запросов.

## neighbors — домены на том же IP (preview)

* Reverse-IP lookup (HackerTarget), оценка риска shared-хостинга.
* Соседи перечисляются в отчёте и графе отдельными сущностями — с целью
  никогда не смешиваются.

## tech — фингерпринтинг веб-стека (preview)

* ~150 маркеров: CMS (WordPress, Joomla, Drupal, Bitrix, OpenCart, Magento…),
  языки/фреймворки (PHP, ASP.NET, Java/Tomcat, Rails, Django, Flask, Express,
  Next.js…), JS-библиотеки с версиями, базы (сигнатуры ошибок + открытые
  порты БД), хостинг-панели, CDN/WAF, инвентарь WordPress-плагинов.
* Read-only пробы, раскрывающие версии (`/readme.html`, `/wp-json/`…), и
  проверки EOL-рантаймов.

## webpaths — обнаружение контента (reference)

* Только GET. Кураторский словарь (≈70 безопасных / ≈200 deep) — лишь посев:
* пути добываются из HTML главной, строковых литералов в скачанных JS/CSS
  (`fetch("/api/lol/admin")` — SPA-маршруты утекают именно тут), robots.txt
  (Disallow/Allow/Sitemap) и sitemap.xml (один уровень индексов).
* Два рекурсивных раунда комбинаций: dir+суффикс, dir+слово, слово+суффикс,
  точечные суффиксы — второй раунд работает по находкам первого.
* Soft-404 базлайн (проба случайного пути) отсекает catch-all/SPA ложняки.
* Каждый подтверждённый путь помнит канал: `page link`, `JS literal`,
  `robots.txt`, `sitemap.xml`, `combination`, `wordlist`.

## exposed — сервисы без аутентификации (reference)

* Строго read-only пробы сервисов, отвечающих без авторизации: Redis,
  Memcached, MongoDB, Elasticsearch, CouchDB, etcd, Docker API, RabbitMQ
  management, Kubernetes API.
* Находка требует, чтобы сервис *отвечал*, а не просто чтобы порт был открыт.

## headers — заголовки безопасности (reference)

* HSTS, CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy,
  Permissions-Policy, CORS, раскрытие версий, флаги cookie.
* В HTML-отчёте — матрица по URL (✓/✗ со значениями по наведению).

## waf — детект блокеров (preview)

* Пассивные подсказки в заголовках/cookie + один активный GET на отпечаток
  блок-страницы.
* Опознаёт WAF/edge-вендоров (Cloudflare, Imperva, Sucuri, Akamai,
  ModSecurity, DataDome, F5, CloudFront, DDoS-Guard…), анти-бот вызовы,
  HTTP 429 rate limiter'ы, гео/регион-блокировки.
* Ставит per-host `scan_visibility`: `full` / `degraded` / `blocked` — чтобы
  неполная картина не выдавалась за полный аудит. Обхода нет никогда.

## cve — матчинг версий (preview)

* Источники версий: баннеры сервисов + веб-стек + базы + CPE от Shodan/Censys.
  Карта CPE на 75+ продуктов.
* Каждый матч — живой запрос к NVD API 2.0 с точной версией
  (`virtualMatchString`); кэш 24 ч; самопейсинг ≈6 с на продукт без ключа
  (~0.8 с с `--nvd-key`); бюджет запросов на скан (15 без ключа / 60 с
  ключом), чтобы большой инвентарь не вешал скан.
* Находки обогащаются ссылками на публичные эксплойты из Exploit-DB.
* Непроверенные матчи честно понижаются (подсказки серьёзности, статус
  `unverified` в графе).

## secrets — паттерны секретов (preview)

* Только высокоточные паттерны: ключи AWS/Google/Slack, блоки приватных
  ключей, общие формы токенов с проверкой энтропии.
* Скан отдаваемого контента + до 8 same-origin JS файлов.
* Доказательства всегда маскируются; в отчёте — замазанный образец.

## Капы и честность

Каждый кап (субдомены, пути, события трафика, вершины карты) отражён в JSON
и помечен в HTML учётовыми плашками — переполнение считается и
предупреждается, а не прячется.
